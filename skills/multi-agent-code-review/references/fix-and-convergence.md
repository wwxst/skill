# Fix & Convergence — 修复与三轮收敛

## 1. 修复授权

默认 `Review Only`，不修改代码。

只有用户明确要求“审查并修复”或“开发完成后自动修复”，才进入 `Review & Fix`。

## 2. 修复规则

只修复经过独立验证、且由本次变更引入或扩大的问题。

- 修复根因，不做表面绕过；
- 同一类问题存在多个实例时，一次性检查和修复所有已知实例；
- 增加或完善回归测试；
- 不删除测试、不弱化断言、不绕过检查；
- 不做无关重构；
- 不覆盖其他会话的修改；
- 需要改变需求或架构方向时，先询问开发者。

## 3. 三轮限制

最多三轮。三轮是上限，不是必须跑满。

### 第 1 轮：完整审查
- 审查完整 diff；
- 并行 Bug Hunt；
- 独立 Voter 验证；
- 运行 Security Review（如适用）；
- 修复确认的问题（仅 Review & Fix）。

### 第 2 轮：只审查新增 diff
- 只检查上一轮后新增或修改的 diff；
- 可读取相关调用链理解修复；
- 检查修复是否引入新问题；
- 不重复报告代码未变化的旧 finding。

### 第 3 轮：最后一次复审
- 继续只看新增 diff 和相关修复；
- 确认旧问题状态；
- 检查新回归；
- 同类问题仍反复出现时，停止局部打补丁，重新评估整体方案。

第 3 轮结束后必须停止。仍未通过则报告 `FAIL` 或 `NEEDS HUMAN`，不得启动第 4 轮。

## 4. 防止重复和无限循环

- 每条 finding 有唯一 ID；
- 记录首次发现轮次、当前状态和处理结果；
- 已报告且代码未变化的问题不得重复报告；
- 历史遗留问题不得伪装成新问题；
- 只报告新问题、修复引入的回归，或有新证据的旧问题；
- 不为了减少轮数而忽略真实 Bug；
- 不为了增加发现数量而制造误报。

## 5. 结束条件

可标记 `PASS`：
- 所有阻断 finding 已修复，或开发者明确接受风险；
- 必需测试、Lint、类型检查和构建通过；
- 适用的 Security Review 已完成；
- 没有未解决的 Critical / High 问题；
- 剩余风险和未执行检查已说明。

不能通过第三轮时必须停止并报告原因。

## 6. Fix Agent 提示词

```text
你是 Fix Agent，只负责修复已经经过独立验证、并且用户授权修复的问题。

你必须先读取：
- references/fix-and-convergence.md
- references/bug-hunting.md
- 本次相关 finding 和项目规则

只修复已确认且属于本次变更的问题。
修复根因，不做无关重构。
同一类问题有多个实例时，检查并修复所有已知实例。
增加或完善回归测试。
不得删除测试、弱化断言或绕过检查。

完成后报告：
- 修改文件；
- 修复内容；
- 对应 finding ID；
- 测试命令和真实结果；
- 未解决事项。

不要 commit、push、merge 或部署。
```
