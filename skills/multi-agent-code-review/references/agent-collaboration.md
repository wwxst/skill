# Agent Collaboration — 子 Agent 交叉沟通与协作规范

本文件每次审查都必须读取。

## 1. 为什么需要两个阶段

多 Agent 审查既要独立判断，也要相互检查。

- 首轮独立审查：避免 Agent 互相影响，尽可能从不同角度发现问题。
- 第二阶段交叉沟通：让 Agent 质疑彼此证据、补充调用链、发现遗漏和纠正误判。

**不能把“独立审查”和“互相沟通”混成同一阶段。**

## 2. 首轮：先独立，禁止提前互相影响

Bug Hunter A、B、C：
- 各自在独立上下文中审查；
- 不读取其他 Hunter 的候选问题；
- 不讨论彼此的判断；
- 各自提交完整首轮结果。

主 Agent 必须等所有首轮任务完成或明确失败后，冻结首轮报告。冻结后不得悄悄覆盖原始判断。

## 3. 第二轮：交叉沟通

首轮结果冻结后，主 Agent 组织交叉讨论。支持两种方式：

### 方式 A：Agent 直接沟通（DIRECT）

如果运行环境提供 Agent 间消息、共享协作会话或等价机制：
- 主 Agent 创建明确的讨论主题；
- 允许 Agent 针对指定 finding 互相提问和回应；
- 每次讨论都必须围绕代码证据和触发条件；
- 主 Agent 负责控制范围和结束讨论。

### 方式 B：主 Agent 中转（COORDINATOR_RELAY）

如果子 Agent 不能直接互发消息，但主 Agent 可以向它们发送后续任务：
1. 主 Agent 将某条 finding 的描述、文件行号、证据和触发条件发给另一名 Hunter。
2. 接收者独立检查代码，给出质疑、确认、反例或补充路径。
3. 主 Agent 把回应转给原发现者，要求其答复证据或修正结论。
4. 主 Agent 汇总双方观点，保留未解决的分歧。

这也属于 Agent 之间的协作，但报告必须写明是由主 Agent 中转，不得称为直接通信。

## 4. 交叉讨论要做什么

至少覆盖以下检查：

- **证据质疑：** 行号和代码是否真的支持该问题？
- **触发条件：** 是否有真实可达的调用路径？
- **影响判断：** 影响是否被夸大或低估？
- **反例检查：** 是否有保护逻辑、校验或测试能阻止问题发生？
- **遗漏检查：** 这个问题是否暗示同一调用链还有其他缺陷？
- **修复建议：** 建议是否会破坏其他模块或引入新回归？

Agent 可以改变首轮结论，但必须说明是什么新证据导致改变。不得为了达成一致而强行统一意见。

## 5. 讨论分工

推荐的默认安排：

- Hunter A 检查 Hunter B 的集成/数据流发现；
- Hunter B 检查 Hunter C 的边界/失败路径发现；
- Hunter C 检查 Hunter A 的行为/根因发现；
- 每个 Hunter 对收到的 finding 至少给出一次有证据的质疑或确认；
- 对高严重度、存在分歧或影响范围较大的 finding，主 Agent 可以追加一轮定向讨论。

不要求每个 Agent 讨论所有 finding。按问题相关性分配，避免无意义聊天和 Token 浪费。

## 6. Voter 的独立性仍然保留

交叉讨论不能污染 Voter 的第一轮独立判断：
- Voter 不读取其他 Voter 的投票；
- Voter 不参与 Hunter 的首轮讨论；
- 每个 Voter 只收到待验证 finding 和必要源码；
- 所有初始投票提交后，主 Agent 才能查看投票汇总；
- 如需第三票，第三名 Voter 仍必须独立判断。

Hunter 之间的讨论不能代替 Voter 验证。

## 7. 沟通能力不足时怎么办

主 Agent 必须在启动前检查：
- 是否支持 Agent 直接互发消息；
- 如果不支持，主 Agent 是否可以向现有 Agent 发送后续消息并收回回应。

如果两种方式都不支持：
1. 暂停完整多 Agent 协作审查；
2. 向开发者说明缺少什么能力；
3. 询问是否接受只做独立并行审查、不做交叉沟通；
4. 未得到同意前，不得静默跳过。

如果开发者同意受限模式，最终状态标记 `MULTI_AGENT_NO_CROSS_TALK`，报告明确指出未执行 Agent 交叉讨论。

## 8. 讨论结束条件

满足以下条件即可结束交叉讨论：
- 所有高严重度 finding 已被质疑或补充验证；
- 每条争议 finding 已有明确证据或被标记 `UNCERTAIN`；
- 没有新的、可验证的证据继续改变结论；
- 已经记录分歧和待处理事项。

交叉讨论不是无限循环。每条 finding 默认最多一轮交叉质疑；重大争议可追加一轮。整个审查仍受最多三轮复审限制。

## 9. 沟通记录格式

```text
Communication ID:
Mode: DIRECT / COORDINATOR_RELAY
From Agent:
To Agent:
Finding ID:
Question:
Evidence Shared:
Response:
Conclusion Changed: YES / NO
Reason:
Coordinator Action:
```

## 10. 不允许的沟通方式

- 首轮独立审查尚未提交就互相传播结论；
- 为了达成共识而压制少数意见；
- 只说“我同意”却不给代码证据；
- 把模型私有思维链当作协作材料；
- 让 Agent 之间无目标地长时间聊天；
- 把主 Agent 中转沟通谎称为 Agent 直接通信。
